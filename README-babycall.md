# BabyCall (赤ちゃん専用ビデオ通話アプリ)

赤ちゃんが**勝手に通話を切ったり**、**他の人に電話をかけたりできない**ことを目的にした、
Android 向けのビデオ通話アプリです。マンガ翻訳アプリとは独立した Gradle モジュール
(`babycall`)として同じリポジトリに同居しています。

## 安全設計の要点

| 心配ごと | 対策 |
|---|---|
| 赤ちゃんが他の人に電話してしまう | 赤ちゃん端末にはダイヤルパッドも連絡先も一切ない。ペアリング時に登録した保護者端末からの着信にしか反応できない構造になっている。 |
| 赤ちゃんが勝手に通話を切ってしまう | 赤ちゃん側の通話画面に「終了」ボタンは表示されない。終了できるのは、画面隅の見えないポイントを3秒間長押しし、さらに保護者が設定したPINを入力した場合のみ。 |
| 赤ちゃんがアプリから抜けて他の操作をしてしまう | 通話中・待機中とも画面ピン留め(Lock Task / 画面固定)を有効にし、ホーム・戻る・タスク切替を無効化する。 |
| 保護者が呼びかけたときに赤ちゃん側の操作が必要 | 自動応答(デフォルトON)。着信すると赤ちゃん端末は何も操作せずにつながる。 |

これらはあくまで「乳幼児が偶発的に操作してしまう」ことを防ぐための設計であり、
悪意のある操作を完全に防ぐセキュリティ機構ではありません。

## Firebase等のアカウント登録は一切不要です

このアプリは **Firebaseや自前サーバーを一切使いません**。どこからでも呼びかけられる
「オンラインモード」は、[PeerJS](https://peerjs.com/) プロジェクトが無料で公開している
中継サーバー(`0.peerjs.com`)を使って、通話相手を見つける「シグナリング」だけを
仲介してもらう方式です。実際の映像・音声はいつも通りWebRTCで直接P2P通信するため、
中継サーバーは会話の中身を一切見ることができません。アカウント登録・サーバー運用・
支払い設定などは何も必要ありません。

## 離れて暮らす家族(祖父母・叔父さんなど)も見られるようにする

**オンラインモード**を使えば、家族なら誰でも、それぞれ別の場所から同じ赤ちゃん端末に
呼びかけられます。赤ちゃん端末を設定したときに表示される番号は**期限なし・回数無制限**の
「家族の合言葉」のようなもので、一度発行したら仕組みを変えない限りずっと使えます
(最初に通話に参加する家族にも、後から加わる家族にも、同じ番号を使います)。

1. 赤ちゃん端末の設定が終わると番号が表示されます。すでに参加済みの家族の端末でも、
   ホーム画面の **「家族を招待する」** をタップするといつでもこの番号を再表示できます。
2. 招待したい相手(祖父母・叔父さんなど)に、その番号を伝えます
   (電話・メッセージアプリなどお好きな方法で。何度でも・何人にでも使い回せます)。
3. 相手はBabyCallアプリをインストールし、**「通話に参加する」** を選んで
   名前と番号を入力するだけで、自分の端末からも同じ赤ちゃん端末に呼びかけられる
   ようになります。**赤ちゃん端末の電源が入っていてインターネットに接続されている
   必要があります**(サーバー上に家族の記録が残っているわけではなく、赤ちゃん端末が
   その場にいて初めて成立する仕組みのためです)。

**通話中でも後から合流でき、全員がお互いの顔を見て話せます。** 誰かが赤ちゃんに呼びかけている
最中に、別の家族が同じ番号を使って呼びかけると、既存の通話を中断せずにそのまま合流できます。
赤ちゃん端末の画面にはつながっている視聴者全員の映像が並んで表示され、視聴者同士もお互いの
映像・音声を直接やり取りします(赤ちゃんの映像を見るだけでなく、離れた家族同士で会話する
こともできます)。それぞれが独立した接続を持つため、誰か1人が退出しても他の人はつながった
ままです。

このグループ通話は、赤ちゃん・視聴者それぞれの端末が参加者ごとに直接接続する方式
(いわゆるメッシュ型)で実現しています。中継サーバーは「誰が誰なのか」を仲介するだけで
映像・音声を中継しないぶん、参加人数が増えるほど各端末の通信量・処理負荷が増えていきます。
家族数人程度の利用を想定しており、大人数向けの設計ではありません。

この仕組みはオンラインモード専用です(ローカルモードは同じWi-Fi内・赤ちゃん1台につき
1系統のみを想定した設計のため、複数人の同時接続はできません)。参加した家族全員が対等な
立場で、誰でも設定画面からPINの変更や自動応答のON/OFFを行えます(家族内の信頼関係を前提と
した設計で、権限を制限する仕組みは現時点ではありません)。番号を取り消す・作り直す機能は
現時点ではないため、番号を知られたくない相手がいる場合はご注意ください。

## 接続方式:オンライン or ローカル

赤ちゃん端末のセットアップ画面で、通話の仕組みを2つから選べます。
**どちらもアカウント登録・サーバー運用は不要です。**

| | オンラインモード | ローカルモード |
|---|---|---|
| 使える場所 | どこからでも(外出先の4G/5Gからでも赤ちゃん端末に呼びかけ可能) | 同じWi-Fiに接続されているとき、または後述の「外出先からの通話」が使える状態のとき |
| 仕組み | PeerJSの無料公開中継サーバーでお互いを見つけ、映像/音声はP2P (WebRTC) | mDNS (NSD) で赤ちゃん端末を自動的に見つけ、生のTCPソケットで直接通信 |
| 対応台数 | 保護者複数台・赤ちゃん複数台に対応可能 | 保護者1台・赤ちゃん1台の組み合わせのみ(シンプルさ優先の割り切り) |
| 信頼性 | 無料の公開サービスに依存(後述の限界を参照) | 自宅Wi-Fi・ルーターの範囲内で完結、外部サービス依存なし |

「自宅Wi-Fi内だけで使えれば十分」という場合はローカルモードを、「外出先からも
呼びかけたい・複数の家族で使いたい」という場合はオンラインモードを選んでください。
ローカルモードの場合、赤ちゃん端末の設定画面に出る番号を、参加する側の端末に入力する
だけでペアリングできます。**ペアリングが完了するまで赤ちゃん端末側のセットアップ画面を
閉じないでください**(その場で一時的に待受けしているだけのためです)。オンラインモード
は番号が発行された時点でペアリング完了で、待つ必要はありません。

### ローカルモードでも外出先から通話できるようにする(ベストエフォート)

ローカルモードは「同じWi-Fi限定」が基本ですが、赤ちゃん端末は起動時に
以下の2つをベストエフォートで自動的に試みます。オンラインモードの中継サーバーとは
別の、それぞれ独立した仕組みです。

1. **UPnP**: 自宅ルーターに「このポートを赤ちゃん端末に転送して」と自動でお願いする。
2. **STUN**: 「インターネットから見た自分の住所(公開IPアドレス)」を、無料で
   公開されているSTUNサーバーに教えてもらう。

両方成功すると、赤ちゃん端末は自分の公開アドレスを、次に呼びかける側の端末と
同じWi-Fiにいるとき(=次回の呼びかけ時など)にこっそり伝えます。呼びかける側の
端末はこれを覚えておき、自宅Wi-Fiの外にいて赤ちゃん端末が同じWi-Fi上に見つからない
ときは、この覚えておいた住所に直接つなぎに行きます。ホーム画面にも
「外出先からの通話: 対応 / 未確認」という状態表示が出ます。

**これが機能するための条件と、正直な限界:**

- 赤ちゃん端末は**自宅Wi-Fi**に接続している必要があります(モバイル回線では
  そもそもルーターを経由しないため対象外です)。
- 自宅ルーターが**UPnPに対応していて、有効になっている**必要があります
  (家庭用ルーターの多くは対応していますが、設定でオフになっていたり、
  機種によっては非対応の場合もあります)。
- 契約している回線が**CGNAT(複数世帯で1つの公開IPを共有する方式)**だと、
  ルーター側の設定に関わらずどうやっても外部から到達できません。近年は
  モバイル回線だけでなく一部の固定回線でもCGNATが使われることがあります。
- 自宅の公開IPアドレスは変わることがあります(ルーター再起動時など)。
  変わった場合、呼びかける側の端末が新しい住所を知るには、**もう一度同じWi-Fi内で
  一度つながる**必要があります(そのタイミングで自動的に最新の住所に
  更新されます)。
- これらの理由により、**確実に動作する保証はできません**。ホーム画面の
  「外出先からの通話: 対応」表示は「前回自宅Wi-Fiで確認できた」という
  意味であり、その後回線状況が変わっていれば失敗することもあります。
  確実性を重視するなら、ルーター設定に依存しないオンラインモードをおすすめします。

## 前提条件

- Android Studio / JDK 17 / Android SDK (compileSdk 34)
- 保護者用スマホ1台 + 赤ちゃん用端末(古いスマホやタブレットで可)1台以上
- それ以外の準備は不要です(アカウント登録・サーバー・課金設定なし)

## ビルドする

```bash
./gradlew :babycall:assembleDebug
```

`babycall/build/outputs/apk/debug/babycall-debug.apk` が生成されます。

## 使い方

1. **赤ちゃんの端末**にインストールし、「赤ちゃんの端末として設定する」→
   接続方式(オンライン/ローカル)を選び、呼び名とPINを入力すると番号が
   表示されます。**ローカルモードの場合はここで画面を閉じずに待ちます**
   (オンラインモードは表示された時点で準備完了です)。
2. **呼びかける側の端末**(保護者・祖父母など、何台でも)にインストールし、
   「通話に参加する」→ 同じ接続方式を選び、1で表示された番号と名前を
   入力して参加します(ローカルモードで複数の赤ちゃん端末が見つかった場合は
   一覧から選択します)。
3. 赤ちゃん端末側で **画面固定(Screen Pinning)** を有効にしておきます
   (下記「画面固定について」参照)。
4. 参加した端末のホーム画面にある丸いボタンをタップすると、赤ちゃん端末が
   自動応答してビデオ通話が始まります。

設定(PINの変更・自動応答のON/OFF・赤ちゃん端末の接続解除)は、参加している
どの端末からでも歯車アイコンから行えます。どちらのモードでも、これらの変更は
**赤ちゃん端末がオンライン(同じWi-Fi、またはインターネットに接続)のときだけ**
即座に反映されます(オフラインの端末に後から届ける仕組みはありません)。

## 画面固定(Screen Pinning)について

このアプリは Device Owner 権限なしでも動くよう、Android 標準の
`Activity.startLockTask()`(画面固定)機能でホーム/戻る操作をブロックしています。
機種によっては、**設定 → セキュリティ → 画面固定** を一度手動でONにする必要が
あります。有効化されていない場合、画面固定は静かに失敗し、通話自体は問題なく
できますが、赤ちゃんがホームボタン等でアプリを抜けられてしまう可能性があります。

より確実に「他のことを一切できない専用端末」にしたい場合は、その端末をこのアプリの
**Device Owner** として登録する方法があります(工場出荷状態の端末が必要、または
`adb shell dpm set-device-owner com.babycall/.call.BootReceiver` 相当のコマンドで
設定)。Device Owner化すると画面固定の確認ダイアログなしに常時キオスク化できますが、
その端末を他の用途に一切使えなくなる・設定を戻すには端末初期化が必要になる、という
制約もあるため、今回のコードには含めていません。必要であれば別途対応します。

## 既知の制限

- **公開中継サーバーへの依存(オンラインモード)**: シグナリングにPeerJSの無料公開
  サーバー(`0.peerjs.com`)を使っています。誰でも無料で使える代わりに、運営側の
  都合による障害・メンテナンス・将来的な仕様変更のリスクがあり、稼働率の保証は
  ありません。また、映像・音声そのものはP2P (WebRTC) で直接通信しますが、Google の
  無料STUNサーバーのみを使っているため、双方が制限の強いNAT配下にいる組み合わせ
  (モバイル回線同士など)では接続できないことがあります。安定させたい場合は
  `WebRTCClient` の `turnServers` に無料/低価格のTURNサービス(例: metered.ca、
  Xirsys、Twilio NTS)の認証情報を渡してください。
- **バッテリー/通信量**: 赤ちゃん端末は常時サービスを起動して着信を待つため、
  充電しながらの設置を推奨します。
- **完全な誤操作防止ではありません**: 画面固定やPINは乳幼児の偶発的な操作を
  防ぐためのものです。
- **ローカルモードの「外出先からの通話」は保証なし**: 上記の通りUPnP/STUNによる
  自動対応を試みますが、ルーターの対応状況やCGNAT、IPアドレスの変化次第では
  失敗します。確実に外出先から使いたい場合はオンラインモードを選んでください。
- **ローカルモードは1対1のみ**: 保護者1台・赤ちゃん1台の組み合わせのみを
  想定しています(複数の保護者端末や複数の赤ちゃん端末を1つのローカル
  ペアリングで扱うことはできません)。複数台構成が必要な場合はオンライン
  モードを使ってください。
- **ペアリング・招待は「今つながっている相手」との一期一会**: どちらのモードも
  サーバー上に家族の記録を持たない設計のため、ペアリングや家族参加には両方の
  端末が同時にオンラインである必要があります(ローカルモードは同じWi-Fiに、
  オンラインモードはインターネットに、それぞれ同時に接続している間だけ)。
- **ローカルモードの通信は平文**: 同じWi-Fi内で完結する前提のため、
  ペアリングや通話のシグナリングは暗号化していません(映像・音声自体は
  WebRTCの仕組みによりSRTP/DTLSで暗号化されます)。信頼できない共有Wi-Fi
  (例: 集合住宅の共用回線)では、familyId+トークンの一致を確認して他人の
  端末からの接続は拒否しますが、より高いプライバシーが必要な環境では
  オンラインモード(TLS)を検討してください。
- **家族の番号がそのまま合言葉です**: オンラインモードは、家族の番号を知っている
  人なら誰でも赤ちゃん端末に接続できる設計です(サーバー側のユーザー登録や
  権限管理がないため)。番号は他人に知られないよう管理してください。
